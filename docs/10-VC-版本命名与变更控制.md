## 1. 发布版本命名规则（对外/注册口径）

格式：**`主版本.次版本.修订版本`**（语义化版本，git tag `vX.Y.Z`）

| 段位 | 变更类型 | NMPA 软件更新映射 | 示例 |
|---|---|---|---|
| 主版本 X | 重大更新：架构/核心算法/核心功能变化，或影响安全性有效性的变更；**注册冻结版本** | 重大软件更新（需提交变更注册/许可事项变更，按指导原则） | 1.0.0（首个注册冻结） |
| 次版本 Y | 里程碑功能新增（不改既有安全语义） | 轻微软件更新（质量管理体系内控制） | 0.3.0（M4 审计链） |
| 修订版本 Z | 缺陷修复（ISS-xxx）、文档修订 | 轻微软件更新 | 0.3.1 |

- **软件发布版本 = git tag `vX.Y.Z`**：tag 即冻结基线（代码+文档+SOUP 清单同 commit）。
- 开发期版本带里程碑后缀（如 `0.3.0-m4a`）仅用于界面/日志辨识，**不作为发布版本**。
- 注册申报口径：发布版本完整值 + 命名规则说明（本节）+ 版本更新历史（CHANGELOG）。

## 3. 变更控制流程（配置管理）

```
变更发起（需求/缺陷/SOUP 升级/临床反馈）
  → 影响评估：触及 SRS？触及 HAZ（MDS-RM-005 §3 强制复审条件）？触及 SOUP？
  → 需求级变更：先改 docs/02-SRS（新编号或 rev 标注，编号永不复用）
  → 实现 + 测试同一变更集内完成（原子性）
  → 追溯矩阵重生成：python tools/trm/gen_trm.py --check 必须零缺口（DoD 门禁）
  → 用户评审批准 → commit（消息引用 ISS/SRS/D 编号）→ 需要时打 tag
```

- **单一主干**：`main` 线性历史；每个里程碑/变更集一个 commit（含代码+测试+文档同步更新）。
- commit 消息规约：`M<里程碑>: 摘要`（特性）/ `ISS-xxx: 摘要`（缺陷）/ `docs: 摘要`（纯文档）；
  正文列决策/需求/测试证据；git 历史即变更记录（62304 §8.1.2 可追溯性载体）。
- 文档变更 = 代码变更同等对待：同库同 commit 同评审（D27）。
- 分支保护建议（入库远端后）：main 禁 force-push；tag 仅发布时打。
