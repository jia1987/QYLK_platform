## 4. 追溯机制（决策 D25，防腐化设计）

```
URD-xxx ──(SRS 表「来源」列)──> SRS-xxx ──(@srs 注解)──> src/ 代码文件
                                    │
                                    └──(@srs 注解 + ctest 注册名)──> tests/ 测试
SRS 全量 ──(tools/trm/gen_trm.py)──> docs/06-TRM（自动生成 + 零缺口校验）
```

- ctest 注册名携带主 SRS ID（如 `SRS-070_audit_log`），`ctest -N` 即可人工核对
- 每个测试源文件头部 `// @srs SRS-xxx ...` 列出全部覆盖的需求
- 每个实现文件头部 `// @srs ...` 列出其满足的需求
- `gen_trm.py` 输出矩阵并对「无代码」「无测试」的 SRS 报零缺口失败（DoD#4）

## 5. 修订规则

- 需求变更：先改 SRS（新编号或版本行内标注修订），再改代码/测试，`gen_trm.py` 重跑，
  同一 commit 内完成（原子变更，git 历史即变更记录）
- 文档冻结：发布版本打 git tag（`vX.Y.Z`，规则见 MDS-VC-010）；tag 即冻结基线
- 本文档链为**中文**（NMPA 提交语言）；提交注册时 pandoc 转 PDF（D27）
